# 斯俪 Slique · 体态 AI 分析后端接口规格

本文档定义体态检测功能所需的后端接口。后端按本规格实现后，在小程序
`miniprogram/config.js` 中填入域名与密钥即可对接，无需改动页面代码。

---

## 1. 总览

体态检测流程分两个阶段，对应两个接口：

| 阶段 | 接口 | 作用 |
|------|------|------|
| 单角度校验 | `POST /posture/validate` | 每上传一张照片即调用，判断是否为合格的「单人全身 + 指定角度」照片 |
| 综合分析 | `POST /posture/analyze` | 三个角度全部通过后调用，返回评分与体态问题 |

用户依次拍摄 **正面 / 侧面 / 背面** 三张照片，每张先经 `validate` 校验，
三张都通过后再由 `analyze` 给出最终结果。

- 协议：HTTPS（微信小程序强制要求）
- 编码：UTF-8
- 鉴权：请求头 `Authorization: Bearer <apiKey>`（apiKey 在 config.js 配置）

---

## 2. 接口一：单角度校验

### 请求

```
POST {baseUrl}/posture/validate
Content-Type: multipart/form-data
Authorization: Bearer <apiKey>
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file` | file | 是 | 照片二进制（小程序用 `wx.uploadFile` 上传，字段名固定为 `file`） |
| `angle` | string | 是 | 角度：`front`(正面) / `side`(侧面) / `back`(背面) |

### 返回（200 OK，application/json）

```json
{
  "pass": true,
  "reason": "",
  "fileId": "f_20260614_abc123"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `pass` | boolean | 是否为合格照片 |
| `reason` | string | `pass=false` 时的**具体**原因，会原样展示给用户 |
| `fileId` | string | 服务端为本张照片生成的唯一标识，供 `analyze` 引用 |

### 校验规则建议（后端实现）

后端应基于人体关键点检测，按以下要点判断 `pass`，并在 `reason` 给出可读原因：

| 检查项 | 不通过时的 reason 示例 |
|--------|------------------------|
| 画面中**恰好一个人**（排除拼图、多人、无人） | `画面中检测到多个人物，请单人拍摄` / `未检测到人体，请重新拍摄` |
| **全身完整入镜**（头顶到脚踝关键点齐全） | `全身未完全入镜，请后退调整距离` |
| **角度匹配**（front：双肩双髋正对；side：身体侧向；back：背对） | `当前为正面照，请按要求拍摄侧面` |
| **图像清晰**（非模糊、非过暗） | `光线不足，请在明亮处重新拍摄` / `图像模糊，请保持稳定后重拍` |
| **姿势规范**（直立、手臂自然下垂） | `请保持自然直立站姿，手臂垂落于体侧` |

> 关键点：用户传「两张正面拼图」时，应判定 `多人` 或 `角度不符` 而返回 `pass=false`。

## 3. 接口二：综合分析

### 请求

```
POST {baseUrl}/posture/analyze
Content-Type: application/json
Authorization: Bearer <apiKey>
```

```json
{
  "fileIds": {
    "front": "f_20260614_abc123",
    "side":  "f_20260614_def456",
    "back":  "f_20260614_ghi789"
  }
}
```

### 返回（200 OK，application/json）

```json
{
  "score": 76,
  "issues": [
    { "key": "neck",     "issue": "颈线前移，头前引趋势",   "detail": "深颈屈肌激活不足，上斜方肌代偿过度" },
    { "key": "pelvis",   "issue": "骨盆轻微前倾",          "detail": "髂腰肌缩短，臀大肌激活不足" }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `score` | number | 挺拔度评分 0–100 |
| `issues` | array | 体态问题列表（建议 1–4 条，按严重度排序） |
| `issues[].key` | string | **问题类型标识，必须取自下方枚举**，小程序据此映射推荐课程 |
| `issues[].issue` | string | 问题简述（展示给用户） |
| `issues[].detail` | string | 肌肉层面说明（展示给用户） |

### `key` 枚举（必须严格使用）

| key | 含义 | 主要检测角度 | 对应课程方向 |
|-----|------|--------------|--------------|
| `neck` | 头前引 / 颈线前移 | 侧面 | 颈线归位 |
| `shoulder` | 圆肩 / 含胸内扣 | 正面、侧面 | 肩背舒展 |
| `pelvis` | 骨盆前倾 / 后倾 | 侧面 | 骨盆归位 |
| `back` | 腰椎曲度异常 / 脊柱侧弯 | 侧面、背面 | 腰背安放 |
| `knee` | 膝超伸 / 膝内扣 | 正面、侧面 | 膝稳养成 |
| `foot` | 扁平足 / 足外翻 | 正面、背面 | 足弓生长 |

> 小程序会根据用户问卷里的场景偏好（居家/办公室/健身房），把同一 `key`
> 自动映射到对应场景的课程。后端只需返回正确的 `key`，无需关心课程。

## 4. 错误处理

非 200 状态码或 `pass` 缺失时，小程序按失败处理（提示重试）。建议：

| HTTP 状态 | 场景 |
|-----------|------|
| 400 | 参数缺失 / 文件格式不支持 |
| 401 | apiKey 无效 |
| 413 | 图片过大（建议后端限制 ≤10MB，小程序侧已压缩） |
| 500 | 模型推理失败 |

错误返回体建议：`{ "error": "可读的错误信息" }`

## 5. 底层识别能力选型（供后端参考）

后端的人体关键点检测可选：

- **第三方 API**：百度 AI「人体关键点识别」、商汤、旷视 —— 接入快，按量计费
- **开源自部署**：Google MediaPipe Pose、MMPose、OpenPose —— 无调用费，需 GPU 服务器
- **自训练模型**：基于标注的体态数据集微调 —— 精度最高，成本最大

体态角度的量化（如骨盆倾斜角、头前引距离）通常由关键点坐标计算得出，
再据阈值生成 `issues`。

## 6. 小程序侧接入位置（你只需改一个文件）

后端就绪后，编辑 **`miniprogram/config.js`**：

```js
const POSTURE_API = {
  enabled: true,                          // ① 改为 true 启用真实后端
  baseUrl: 'https://api.your-domain.com', // ② 填后端域名（不含末尾斜杠）
  apiKey:  'your-secret-key',             // ③ 填鉴权密钥（无则留空）
  timeout: 15000,
}
```

同时在 **微信公众平台 → 开发 → 开发管理 → 服务器域名** 中，把后端域名
加入 **request 合法域名** 和 **uploadFile 合法域名**（两处都要加）。

完成后：

- 小程序自动改走真实接口，照片会被实际识别、不合格会被拦截
- 若 `enabled=false` 或 `baseUrl` 为空，自动降级为本地模拟（demo 占位）

> 通信封装在 `miniprogram/utils/postureApi.js`，页面逻辑在
> `miniprogram/pages/scan/scan.js`，正常情况下**无需改动**这两个文件。
